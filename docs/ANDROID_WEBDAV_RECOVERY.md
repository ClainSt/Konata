# Android WebDAV 弱网恢复实测

在 Android 16 手机 2407FRK8EC 的正式 WatchPage 上播放真实 WebDAV 的《86》第一集。每轮清除隔离库内的续播位置，完整观察片头 75 秒媒体时间。缓冲统计来自首帧以后播放器发出的 buffering 状态变化，计入首帧后仍在进行的起始缓冲。首帧时间从打开播放页到纹理首帧回调。应用保持默认 32 MiB 前向缓存，cache-pause-initial=no，预览关闭。两组仅改变 cache-pause-wait；比较次序为 1、15、15、1 秒，首轮还包含冷启动开销。测试反复核对 2.4 GHz 频段与自动简中选轨。

natural 为原链路，paced 为在手机测试包内对同一真实 WebDAV 视频响应设置 1,350,000 字节/秒总上限；所有请求的共享上限用于重建之前观测到的低吞吐，不限制独立字幕请求。product 用同一限速，但从应用开关启用候选策略，禁用自定义 mpv.conf。

限速下最后一次基线在 45 秒内未得到首帧，没有可统计的 75 秒窗口，单列为未完成；首帧超时原因未定位。完成的样本显示较长恢复阈值明显减少重复中断，但累计等待增加，因此保留默认行为。Android 的「弱网 WebDAV 播放」开关仅在下一次 Android WebDAV 主播放时覆盖这一个 mpv 参数。关闭即可恢复原配置，不需要下载额外组件。

在真实链路与限速测试中均核实自动选中简中 .sc.ass。限速下对 7.216 秒的带字幕和去字幕回读作了 SHA-256 比较，并与既有成功截图哈希核对。整个实验覆盖高码率片头，未覆盖整集或其他设备。原始逐轮读数、缓冲区间、字幕像素哈希及超时记录见[测量 JSON](verification/android-webdav-recovery-20261106.json)。

## 2026-11-07 平板冷起播与片尾续播复核

小米 Pad 6S Pro 12.4，03:40 正式候选，2437 MHz，默认播放器配置。点《86》第一集的“继续”，出现黑屏；展开控件可见 23:41 / 23:41，暂停状态，点回 00:43 后出画。这种片尾黑屏可与起播时的 502 区分。

- 在约 01:02 和 22:39 之间暂停跳转，三个往返共六次。按时间轴至实际画面首次显著变化，依次观测到 4.14、5.55、2.65、2.65、2.63、2.67 秒。通过 USB 抓取屏幕采样，数值包含截图延迟，只能作为出画耗时的上界。此轮未做指定帧的 PTS 比对。
- 从详情页重新进入同一集四次，按“继续”至首次采到影片画面的上界依次为 8.30、4.39、5.49、4.98 秒。对应播放中继日志均为上下游 206。每次重新打开播放页，上游缓存冷热未知。已有[候选版失败记录](verification/release-quality-20261107.md)中的 502 成因仍待捕获。
- 修复后，从历史中读取播放起点时，若已到片尾或距离容器末尾不足一个很短的窗口，从片头播放。窗口取片长的 1%，最多 250 毫秒，边界含等号。仅计算启动位置，历史中的原始毫秒数、观看区间与手工标记均保留。无需数据库迁移或额外缓存。
- Windows 和上述平板分别使用隔离测试库、实际 WatchPage 和 4 秒 H.264 合成片，通过 WebDAV 中继复测。写入 3965 ms 的书签，等待首帧后，两端均读到片头 375 ms 且仍在播放。复测入口为 [webdav_resume_test.dart](../integration_test/webdav_resume_test.dart)，通过 `DAV_RESUME_FIXTURE_ROOT` 指向提供 h264-8-1080.mkv 且支持 HTTP Range 的测试媒体源。
- 启用调试日志后，中继现在记录最终响应头耗时、所处阶段与错误类型。可区分上游直接返回 502、等待响应头超时、206 区间无效。三个分支由本地 HTTP 回归覆盖；真实服务下次失败时需结合当次日志归因。保留 5 秒 mpv 默认超时与现有重试行为。

本轮涉及的 6 个 Dart 文件通过静态检查，完整单元及组件回归 306 项通过、9 项跳过。未增加依赖或打包媒体，未制作新版正式发布包。平板上移除了临时测试应用及 USB 转发，关闭了本轮启用的调试日志。完整三轮资源测量仍待进行。
