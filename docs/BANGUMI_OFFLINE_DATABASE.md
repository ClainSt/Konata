# Bangumi 离线数据库使用与更新

本功能面向 1.0.0+2006；1.0.0+2005 及更早版本没有此入口。

离线数据库属于核心刮削的按需数据资源，不随安装包附带。它用于动画名称与正式别名识别；详情、海报和剧照仍按需联网获取。缺失或有歧义的名称继续联网核对，冲突保留待确认。

## 首次安装与日后更新

1. 打开「设置 → 刮削服务 → Bangumi 离线数据库」。
2. 点击「检查更新」，查看官方快照名称和下载大小。
3. 点击「下载／更新」，等待下载、校验和建立索引完成。界面显示条目数和索引大小。
4. 日后在同一页面再次检查更新即可，无需重新安装 Konata 或手动替换数据库文件。

仅在用户点击时检查或下载，没有启动时自动检查和定时下载。下载的是刚展示的快照。当前官方资源是全量 ZIP；Konata 不会把全量下载描述为增量更新。建议使用稳定的 Wi-Fi，并留出下载与导入所需空间。

更新不会主动重新刮削已有媒体库或覆盖手工修改；新索引用于下次扫描或主动重新刮削。

## 网络不便或多设备使用

点击「官方快照下载」，从 [bangumi/Archive Releases](https://github.com/bangumi/Archive/releases) 获取 ZIP，然后点击「导入官方 ZIP」。不用解压，也不要选网页文件或其他软件的 SQLite 数据库。

可以把同一份 ZIP 传到 Windows、手机和平板分别导入，减少重复下载。ZIP 改名也不会影响内容识别；检查更新时通过 SHA-256 判断它是否与官方当前快照相同。用户选择的原始 ZIP 不会由 Konata 自动删除。

直接下载会验证官方清单的 SHA-256；离线导入会校验 ZIP 内容完整性并计算 SHA-256，但在未联网对照官方清单前，不能把本地任意 ZIP 的来源视为已认证。请从上述官方来源获取文件。

## 取消、失败和清理

- 下载可以取消，关闭更新页也会取消当前任务；下次下载相同快照会续传已保存部分。若上游不支持 Range，会重新下载并校验。
- 下载失败、校验失败或导入取消时，已安装索引保持可用。新索引完整建立并通过检查后才替换旧索引。
- 更新成功后删除下载临时文件和构建临时文件。取消下载时保留部分 ZIP 供续传；取消导入时清理构建文件。Android 系统文件选择器产生的本次 ZIP 缓存副本也在导入结束时清理，不清理其他选择任务的文件。意外退出遗留的构建目录在下次更新或移除时清理。
- 「移除索引及下载临时文件」只删除可重建的离线数据，不删除媒体库、观看记录或用户选择的原始 ZIP。
- 程序升级时保留 Windows 整个 `userdata`，离线数据库一并保留；Android 正常覆盖安装保留应用数据。卸载应用或清除 Android 应用数据会移除离线索引，可重新导入。

## 存储与成本

Windows 索引位于程序旁的 `userdata/bangumi_index`；Android 位于应用私有数据目录。复用现有 archive、crypto 和 SQLite 依赖，不增加数据库运行库，不后台下载图片。

2026-11-03 官方 ZIP 为 450,262,892 字节，当前精简索引含 31,297 条动画、约 10.2 MiB。导入过程中会同时保留旧索引、下载 ZIP、精简中间文件和新索引，不能按最终约 10 MiB 估算临时空间。实现限制 ZIP 为 768 MiB、精简数据和索引各 128 MiB；将来官方资源超过限制时会拒绝更新并保留旧库，需评估后更新应用。

Windows Flutter 测试环境最新一轮完整导入（包含 SHA-256 计算）为 24.5 秒，测试进程峰值 RSS 约 188.4 MiB，包含 Flutter 测试环境，并非应用增量内存或 Android 实测；同轮还并行运行了其他回归，不能作为跨设备性能承诺。本轮 Android 实机导入：Redmi K70 Ultra 41.1 秒、Xiaomi Pad 6S Pro 27.3 秒；完整更新分别 43.3 / 26.7 秒，最终索引均 10,706,944 字节。测试进程峰值 RSS 分别 351,531,008 / 282,611,712 字节，是整个验收进程占用，不是功能增量。CPU/GPU、电量未测。

官方格式与发布说明：[Bangumi Archive](https://github.com/bangumi/Archive)。TMDB 每日 ID 导出不等于完整离线资料库，本功能不将它作为中文/日文/罗马音完整别名库。

官方 raw 域名连接失败时，会尝试同一官方文件的 GitHub API 入口，始终保留 TLS 证书校验。Android 在每次请求及重定向时读取系统代理选择器，遵循 HTTP 代理、PAC 和绕过规则，不自动增加直连回退，也不更改用户代理配置；无法读取或不支持的代理类型会明确失败。

本轮平板原先在 FlClash 开启时持续握手失败；接入系统代理后，保持代理开启的更新检查、GitHub 实际下载重定向及取消后 Range 续传通过（约 1 MiB 后取消，再续传约 1 MiB）。手机直连检查通过，但同一轮 github.com 下载连接超时，不能宣称任意网络都可下载。当前网络、代理节点或上游不可用时，旧索引继续可用，也可导入在另一台设备下载的官方 ZIP。

代理桥接复用系统与 Flutter 通道，不增加依赖、监听器或后台轮询，只在用户更新时调用；CPU/GPU 和电量影响未量化。系统接口说明：[Android ProxySelector](https://developer.android.com/reference/java/net/ProxySelector)、[Dart HttpClient 代理](https://api.dart.dev/dart-io/HttpClient/findProxy.html)。
