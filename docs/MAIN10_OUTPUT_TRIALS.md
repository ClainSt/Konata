# Main10 第二轮本地播放实测

2026-11-06。在 Android 真机比较直接硬解、回拷硬解和软件解码；在同一台 Windows 机器比较默认 Flutter 纹理和原生 D3D11。两端沿用当前默认设置。Windows 原生验证路径修正了全屏控制栏隐藏后 Esc 的焦点问题。

## 素材与采样

从本机《86》第一集约 90 秒处以 FFmpeg stream copy 截取测试段，只保留原视频与首条音轨。测试段为 1920×1080、24000/1001 fps、HEVC Main10 SDR、FLAC，SHA-256 为 32f807e9c42ce8039791552b49c578dce72ec60464042d5aaba0ae67c504bec0。手机通过 USB 预先传入测试私有目录，两端都从本地打开。画质比较选 51.5 秒暗色外套镜头，手机实读 51.510 秒。比较同一衣料区域，取视频宽度 17.5%–32%、高度 28%–67%。先配准独立解码帧，再以截图原始像素统计灰度。区域内既有渐变也有纹理，所以相邻像素相同的比例只作描述，不能单独判定色带或主观优劣。

## Android

2407FRK8EC，Android 16，USB 连接且供电，系统自动亮度；开始时亮度读数 45。正式 WatchPage 中逐一切换 mpv 的 hwdec，并重新寻址，读取实际生效路径。三组依次测量，每组从约 5.09 秒播放 60 秒，不跨循环；分别记录起止丢帧、Android 电池温度与系统温控服务的 SOC 读数。

| 路径 | 实际像素格式 | 解码 / 呈现丢帧增量 | 电池 °C | SOC °C | 暗部与软解平均绝对差（8 位灰度） |
|---|---|---:|---|---|---:|
| mediacodec | 不透明 mediacodec | 0 / 0 | 36.0 → 36.0 | 53.25 → 52.06 | 0.033 |
| mediacodec-copy | yuv420p | 0 / 0 | 36.4 → 36.5 | 52.21 → 51.38 | 0.364 |
| 软件 | yuv420p10 | 0 / 0 | 36.5 → 36.6 | 54.24 → 59.26 | 参考 |

合成截图的同一暗部区域为 176×268 像素。直接硬解、回拷、软解的灰度范围分别为 19–33、18–33、19–33。直接硬解在这帧上与软解更接近。一次 USB 供电下的固定顺序短测可揭示现象，不能用于排列整集耗电、稳态温升或跨机型表现。

三种路径各做了真实 Home → 桌面 → 返回已有 Activity。返回后均保持暂停。另一次补测中，手动继续后约三秒内媒体时间均前进超过三秒，直接 / 回拷 / 软件解码的呈现丢帧分别增加 3 / 5 / 0，解码丢帧均为 0。恢复后重新定位到 51.510 秒并采集屏幕，各路径与各自恢复前的同一暗部裁区平均绝对差均为 0。UI 恢复、进度推进与图像恢复分别验证。三种模式在同一已启动的播放页切换，本轮未比较冷启动解码器初始化。

## Windows

当前屏幕为 3200×2000、165 Hz、SDR、RGB full / G22 / P709。由测试驱动通过正式播放页全屏按钮进入、隐藏控件后使用 Esc 退出，并确认能够继续播放。用 Windows 桌面像素拷贝取得前台测试窗口客户区，在相同的 3200×2000 全屏和 3200×1800 视频区域比较。裁区为 (560,604) 到 (1024,1306)，共 464×702 像素。

| 路径 | 实际解码 | 灰度范围 | 平均灰度 | 横向相邻灰度相同比例 |
|---|---|---|---:|---:|
| 默认纹理 | d3d11va-copy / p010，vo=libmpv | 18–33 | 26.638 | 81.64% |
| 原生 D3D11 | d3d11va / p010 硬件表面，vo=gpu，rgb10_a2 输出请求 | 18–33 | 26.624 | 84.08% |

两条路径同一裁区的逐像素灰度平均绝对差为 0.107/255。测试覆盖了桌面合成后的可见画面；8 位截图无法分辨面板输出的 10 位最低有效位，也不能测量面板抖动、亮度或 HDR 表现。基于当前屏幕与样片，没有足够收益将原生路径提升为默认。

![Windows 同一裁区，左为默认纹理、右为原生 D3D11](verification/main10-windows-shadow-trials.png)

两条路径都进入 3200×2000 全屏并恢复至 2534×1369 客户区。原生路径在第一次回归中出现控制栏收起后 Esc 未退出，窗口仍处于全屏。修复后，进入原生全屏时焦点显式移回播放页；再次通过按钮、Esc 和续播测试。默认纹理维持原有按键逻辑。

悬停回归还发现，这段流复制样片的首章在容器内从 0 开始，而 mpv 以首个可呈现时间为基准，实际报告 -0.083 秒。此前章节列表过滤掉了这个合法开场章节。现在将位于可播放起点之前的首章映射到 0 秒；已验证原生窗口的控制栏悬停、章节显示、窗口缩放、寻址与退出。此次键盘和播放器功能专项 9 项通过，改动文件静态分析通过。两端均使用调试验证构建。

## 复测

基准入口为 integration_test/local_mpv_baseline_test.dart。指定 BASELINE_VIDEO 后，可用 BASELINE_ANDROID_TRIALS=true 运行三组解码，或用 BASELINE_WINDOWS_SCREEN=true 验证桌面交互。Windows 原生组另设 CCPLAYER_NATIVE_SDR_OUTPUT=true。Android 正式播放前使用 BASELINE_STAGE_URL 暂存样片，测试包使用 CCPLAYER_ISOLATED_VALIDATION=1。Android 的 frame 标记对应 adb exec-out screencap -p；start/end 对应 dumpsys battery 与 dumpsys thermalservice；background 后发送 KEYCODE_HOME，验证桌面焦点，再启动已有 Activity 使任务返回前台。恢复补测使用 BASELINE_TRIAL_SECONDS=3，只验证生命周期，不计入上表的 60 秒结果。Windows 在 controls 标记将鼠标移到窗口底部，hide 后移开，fullscreen_frame 标记采集前台客户区。各次测量采用独立数据库与临时目录。
