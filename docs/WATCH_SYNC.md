## 2026-11-07 已确认的续播规则

两端使用用户单独配置的 WebDAV 同步目录。对于已经确认属于同一逻辑剧集的文件，采用**位置最后一次实际更新的时间**决定续播秒数，包括两端离线后发生的更新。较晚的回看可以覆盖较早但播放得更远的位置。不同剪辑共享这一秒数；目标时长较短时截到片尾。观看覆盖区间的证据继续按各版时间轴计算。位置同步须使用播放位置的更新时间，手工标记已看、上传时间和下载时间均不能替代。双端传输与真实目录的重试验收尚待实现。

## D2.3 续阶段：事件保存与历史入口

### 已实现

- SQLite16→17仅新增watch_events和watch_event_local及事件查询索引；旧作品、文件、观看区间、人工绑定与身份确认记录不批量改写。
- 每个安装数据目录生成独立随机设备身份、事务内递增序号；事件ID独立于路径、来源及设备时间。事件格式版本1，不包含原始路径、URL、令牌或视频哈希。
- Catalog.progress在同一事务内保存物理进度及已确认身份的新观看证据；失败一起回滚。没有身份时继续原来的物理保存，不把猜测送入事件表。历史手动标记也与人工事件同事务保存。
- 证据由设备、物理asset ID及实际时长区分时间轴。同一流跨会话合并区间，重复快照不新增事件；不同文件、设备或时长不拼接、不做比例换算。只保存新调用中提供的实际区间，不把旧播放位置或旧时长的progress区间转成新事件证据。
- coverage事件包含区间、时长和当次阈值。合并状态重新计算区间覆盖率，不信任最大播放位置或外部completed标志。任一独立流已达阈值可贡献自动已看；未达阈值的不同流不会相加。

## D2.2：持久身份基础（部分实现）

SQLite v16 新增 logical_episode_confirmations 表及按 asset_id/id 索引。原表、资产和进度不改写。迁移使用现有 onUpgrade 事务，不遍历确认旧刮削数据。

Catalog.logicalEpisodes 暴露 LogicalEpisodeStore：

- confirm(assetId, expectedKey) 在事务内核对调用方审阅的候选，追加确认记录；候选变化或缺失时失败。
- resolve 优先查询当前人工关系；人工“其他”、不一致作品及无法确认的编号阻止旧确认。其次只接受与当前候选匹配的最新有效确认。
- revoke 追加撤销记录，重复撤销无操作，不改物理文件或播放区间。它撤销的是显式候选确认；已有人工季集关系仍由原来的人工关系撤销入口管理。
- 人工明确指定的 TMDB 季0特别篇可产生 s0 键；未确认 extra 仍拒绝，电影、无作品/季/集不合并。不从 SP/OVA 文件名猜编号。
- Windows 本地、Android WebDAV 路径及编码不进入逻辑键；资产 ID 不变的改名保持身份。删除后以新资产 ID 重建的文件仍需重新确认，不能用路径相似度继承确认。
- 确认记录保留审计用途；删除资产后不清除确认记录，resolver 的资产查询保证孤立记录不能变成有效映射。

这仍是服务层基础：未增加自动候选确认界面；未将逻辑身份接入播放状态合并、事件日志或远端队列。人工关系解析在查询时复用原持久表，不重复保存一套容易失配的人工数据。不能宣称“跨版本已看共享”已完成。

不同版本的时长、位置及观看区间完全独立，没有按时长比例或最大位置换算。尚需事件模型处理离线并发、手动未看、重复上传及冲突，再进行下一阶段。
